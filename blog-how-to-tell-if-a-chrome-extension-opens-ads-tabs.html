How to Tell If a Chrome Extension Opens Ads Tabs

November 23, 2026 · 10 min read · Prompt Helper

"This extension opens advertising tabs by itself." That is one review on a prompt extension with 100,000 users and a 2.8 average rating. The same reviewer went on: "If I wanted pop-up adware, I would not have installed a prompt manager."

How to tell if a Chrome extension opens ads tabs: you cannot rely on the install dialog. Chrome does not warn about it, because opening a tab needs no permission at all. Below we read 566 reviews across 149 prompt and writing extensions and unpacked 24 published packages to find where the signal really hides.

How to tell if a Chrome extension opens ads tabs

Start by ruling out the thing everyone else checks. The store listing shows permissions, and the install dialog shows a warning for the sensitive ones. But an extension that force-opens a promotional tab is doing so with the tabs.create API, and Chrome's own documentation notes that this does not require any permissions:

"This example doesn't require any permissions"

That is the whole problem in one sentence. The tab-opening behavior sits outside the permission system entirely. An extension can request nothing scary, install without a single warning, and still open whatever it likes. The permission list is not evidence of safety, and the absence of a warning is not evidence of absence.

The second place people look is the source code, often by grepping the package for known ad network domains. We tried that and it failed in an instructive way. Across 24 published packages we found 400 occurrences of strings that look like ad network hostnames. 398 of them were false positives. 369 were React event handlers for the double-click gesture, 24 were cosmetic filter lists inside a bundled article readability library, and 5 were ordinary identifiers such as a content-length field. A string scan is not a safety signal, and a grep that finds an ad hostname is very probably telling you about a double-click handler.

Why the install warning will not tell you

Chrome's permission warning system is real, and it works the way the documentation describes. Some permissions are quiet and some are loud: "Some permissions are less intrusive and don't display a warning. Other permissions trigger a warning that users have to allow." That part is documented. The catch is which permissions get folded into which others.

The documented example is worth reading twice. Chrome states that the "tabs" warning won't show if the extension also requests "<all_urls>". An extension that asks for every site is allowed to read every tab, and Chrome suppresses the narrower warning that would have flagged it. The warning you see depends on the rest of the permission list, and a broad permission can make the list look calmer than the underlying access.

Chrome offers activeTab as the quiet alternative. It "gives an extension temporary access to the currently active tab when the user invokes the extension" and "displays no warning message during installation". That is a fair trade for a tool that only needs the page you are looking at. It is also a reminder that an install screen showing one warning is a snapshot of one permission, not a verdict on the whole extension. The activeTab reference spells out the trade in full.

Where the signal actually lives: the review bodies

We collected the listings for 149 prompt and writing extensions, with 566 reviews between them. 94 listings had at least one review and 55 had none, so most of this category has a thin public record. That matters, because the review text is where the tab-opening complaint surfaces, and there is very little of it.

Exactly one listing in the set carried ad-tab complaints, and it carries three distinct ones. The reviewer who reported the behavior described watching it happen without consent: "This extension opens advertising tabs by itself." and "without any click or consent." A second reviewer wrote "The extension secretly opens new Chrome tabs that load promotional pages. These ad pages interrupt work and erode trust. An add-on that injects unsolicited advertising belongs nowhere near my browser." A third flagged the pattern across the category rather than one product: "WARNING!, makes extremely penetrating advertising".

The extension's own developer answered two of those reviewers and confirmed the behavior rather than denying it. To the second: "We offer a pro version for users who prefer an ad-free experience." and "Additionally, we limit ad popups to twice per month." That last sentence is the whole disclosure, and it is also the reason the complaint keeps recurring: the paid tier is where the ads stop.

Now the reason this is hard to catch. The listing shows a 2.8 average from 161 ratings. Two point eight is low, but it is low for a mix of reasons, and nothing in the star figure says which. A reader who sees 2.8 and moves on has lost the information. The reviewer who wrote about the ad tabs had it flagged as helpful by 11 other people, which is a stronger signal than the aggregate ever gets to be. The full thread is in the AI Prompt Genius review page.

Read the manifest, not the store description

The manifest is the one part of an extension you can read without installing it. It tells you which API permissions were requested, which hosts were granted, and whether the package can open tabs at all. We unpacked 24 published packages and counted.

  • 7 of 24 requested <all_urls>, access to every site on every page.
  • 9 of 24 requested the tabs permission, which exposes tab URLs and titles.
  • 16 of 24 contain a tabs.create call, and 2 of 24 can open a new window.
  • Permission counts ran from 1 to 28, with a median of 3. 9 packages requested 5 or more API permissions.

The tabs permission is worth understanding, because the name oversells it. Chrome documents that it "does not give access to the browser.tabs namespace. Instead, it grants an extension the ability to call tabs.query() against four sensitive properties on tabs.Tab instances". What it really adds is the ability to see where you are. Host permissions are the broader grant: they "allow an extension to read and query a matching tab's four sensitive tabs.Tab properties" and to inject scripts into matching pages.

So the manifest narrows the question. It cannot tell you whether the extension opens a tab on a timer or after every fifth prompt, but it tells you what the extension could reach if it did, and a tabs.create call with a remote URL in it is worth reading.

One package did hide an ad system in plain sight

Of the 24 packages, exactly one had a real ad system rather than a coincidental string. A developer tool called Merlin Glass, version 0.1.7, ships a function named initAdSystem containing three rotating promotional links to font and texture marketplaces. Its manifest requests only activeTab and scripting, so the install screen is quiet. Its code calls tabs.create zero times, so it does not open tabs. It renders the ad in its own panel instead.

That case is instructive because it shows how ad code hides. It was not found by searching for a known ad domain. It was found by searching for the word ad in function names, which surfaced a function that no string scan for ad networks would have caught.

What Prompt Helper actually ships

Since this article is about transparency, here is our own package, read from the published version 2.7.22 rather than from a development tree.

  • 3 API permissions: tabs, storage, identity. The identity permission is what makes Sign in with Google work.
  • 15 host permissions, every one of them a named AI site such as ChatGPT, Claude, Gemini, Grok and Perplexity. No <all_urls>.
  • 5 tabs.create calls, all of them user-initiated: the welcome page after install, the Stripe checkout page, the customer portal, and the leave-a-review link.
  • 0 windows.create calls and 0 notification API calls.
  • 0 permissions.request calls. The one occurrence of <all_urls> in the package sits inside a permissions.remove call that revokes a legacy all-sites permission on install, which removes access rather than adding it.

That last bullet is the one worth copying. The live listing describes an optional rewrite button on any site that is off by default, and the package actively revokes the old blanket permission that used to back it.

A five-minute checklist before you install

  1. Read the one and two star reviews, not the average. Search the text for tabs, opens, popups, and advertising.
  2. Open the manifest. Count the permissions, and check whether <all_urls> is present.
  3. Look for a tabs.create call with a remote URL in it, and for functions whose name contains ad.
  4. Check whether the developer answers complaints about advertising. A reply that confirms the behavior is at least honest about it.
  5. Compare the store rating against the review count. A 2.8 from 161 ratings is a different signal from a 2.8 from 7.

Key takeaways

  • Opening a tab requires no permission, so the install warning cannot flag it.
  • A broad <all_urls> request can suppress Chrome's narrower tab warning entirely.
  • Grepping for ad domains produced 400 hits, 398 of them false positives.
  • The signal is in individual review bodies, not in the star average.
  • The manifest tells you what an extension can reach. Only the reviews tell you what it does with it.

Frequently asked questions

Does Chrome warn me if an extension will open ads tabs?

No. Opening a new tab needs no permission at all, so the install dialog stays silent about it. Chrome only warns on permissions such as reading browsing history or accessing every site. A prompt or writing extension that quietly opens promotional tabs produces a clean permission list, a clean install screen, and no warning you can act on.

Where do I actually look for the ad-tab signal?

The review text, not the rating. Aggregate stars bury a specific complaint that a few reviewers repeat. Read the one-star and two-star reviews and search for tab-opening language. One extension in our sample of 149 listings carried a 2.8 average from 161 ratings, and the tab-opening complaint only appears in the individual review bodies.

Is a low star rating enough to disqualify an extension?

It is a reason to read the reviews, not a verdict. Low ratings also come from bugs, login failures, and missing features. What matters is the shape of the complaint. Tab-opening and browsing-history complaints describe what the extension does to your browser, which is a different category of problem from a feature that does not work.

Does checking the manifest tell me whether ads will open?

It tells you what the extension is allowed to do, which is useful but not conclusive. The manifest shows which permissions and hosts were requested. It does not reveal which tabs the extension opens, or whether it opens them on a timer. To answer that you need the reviews, or you need to read the packaged code yourself.

How do I remove an extension that is already opening ads tabs?

Remove the extension first, because that ends the behavior regardless of what else is wrong. Google lists unwanted Chrome extensions that keep coming back as a symptom of unwanted software. Then run a Safe Browsing check and confirm the extension is gone from the extensions page rather than merely switched off.

How to tell if a Chrome extension opens ads tabs: what to do next

To tell if a Chrome extension opens ads tabs, start where the install dialog cannot go. Read the review bodies for tab-opening language, then open the manifest and check what the extension requested. Prompt Helper ships 3 API permissions and 15 named host permissions, opens no windows, and never calls a notification API. If you want that transparency in the tools you install, the manifest and the review text are where you will find it.

If the extension is already installed and behaving this way, start with Google's own unwanted software and ads guide, which lists unwanted Chrome extensions that keep coming back among the symptoms of a problem, and then remove the extension rather than merely switching it off.
